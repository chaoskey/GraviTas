# 方法 · 怎么用这台问题牵引机

## 1. 一个问题档案怎么读

每个 `problems/Pxx.md` 结构相同，**不要从头读到尾**。建议的读法：

1. **只读"一句话"和"为什么是入口"**（2 分钟）。判断：这个问题现在对你有意义吗？
2. **跳到"必读文献"**，选**一篇**最难的、看起来最不舒服的，先读它的摘要和引言。
3. **回到"核心公式"**，挑一个公式，试着自己推。推不动 → 带着具体问题回去读文献。
4. **自检问题**是通关条件，不是装饰。答不出就别标记 `completed`。

> 档案里的"当代状态"会过期。每 6 个月至少更新一次你正在攻的那个。

## 2. 两周一个循环（Loop）

```
D1  定位     写下"我现在对这个问题的一句话理解"（必须能贴到墙上）
D2-3 进攻    读 1 篇论文 + 推 1 个公式；卡住立刻记进 log
D4-6 复现    合上论文，从白纸重推；允许查定义，不允许查步骤
D7  输出     写笔记（不是摘要，是"我自己的推导"）
D8  讲解     讲 20 分钟给一个人/录音；标出所有讲不顺的地方
D9-12 补洞   只补"讲不顺"的那几处，不要发散去读新东西
D13 归档     更新档案的"我的笔记"链接 + log
D14 决策     继续 / 换问题 / 降难度
```

**核心约束**：D9–D12 只能补洞，不能开新战场。这一条能救你 80% 的时间。

## 3. 三种笔记，别混用

| 类型 | 位置 | 写法 | 反例 |
|---|---|---|---|
| **推导笔记** | `notes/N###-*.md` | 从假设到结论，每步可检查；标出"我一开始错在哪" | 抄书 |
| **问题档案** | `problems/P##.md` | 地图：定义、现状、文献、路径 | 写成教程 |
| **日志** | `log/YYYY-MM-DD.md` | 今天卡在哪、明天干什么、情绪如何 | 写读后感 |

推导笔记的硬标准：**三个月后你自己能只看笔记重现这个推导，不需要原论文。**

## 4. 读一篇论文（三遍法）

- **第一遍（15 min）**：标题、摘要、引言最后一段、结论、图。回答：它声称解决了什么？
- **第二遍（1–2 h）**：跳过技术细节，看每一节的第一段和最后一个公式。回答：论证的骨架是什么？哪一步是"魔法"？
- **第三遍（半天到一周）**：只挑**一步**复现。通常是最关键的那一步，或你最不信的那一步。

> 永远不要"第三遍读整篇"。读完一篇论文 = 复现了它的一步。

## 5. 怎么判断自己懂了（费曼测试）

合上所有材料，用**没有公式的语言**讲 5 分钟，然后回答三个问题：

1. 如果把这个理论的某个假设改掉，会发生什么？
2. 这个结论的反例长什么样？
3. 我能举一个它**不能**解释的现象吗？

三个都答得出 → 懂了。只能背定义 → 没懂。

## 6. 卡住了怎么办（决策树）

```
卡住
├─ 卡在"不知道这个词什么意思" → 查 glossary / 教材目录，15 分钟上限
├─ 卡在"这一步怎么来的" → 找 2 篇不同作者的讲法，对比差异
├─ 卡在"算不出来" → 退化到 0+1 维 / 平直空间 / 自由场，先算玩具版
├─ 卡在"不知道为什么要这么算" → 回到问题的物理动机，问"如果不这样会怎样"
└─ 卡超过 2 周 → 带着洞前进，log 里写清楚洞在哪，设 1 个月后回访
```

## 7. 工具

- **纸笔优先**。手推是唯一不会骗你的方式。
- 符号计算：`sympy`（免费）、`xAct`/`xTras`（Mathematica，张量计算神器）。
- 绘图：Penrose 图手画；数值用 `matplotlib`。
- 版本控制：本仓库。**每次输出都提交**，commit message 写"今天搞懂了什么"。
- 不要用 AI 替代推导。可以问"这一步为什么成立"，但不能让它替你算完然后你点头。

## 8. 写作标准（给未来的自己看）

- 每个符号第一次出现必须定义。
- 每个"显然"都要能展开成三行。
- 每个结论后面跟一句"这意味着什么"。
- 允许写"我不知道"，不允许写模糊的"可以证明"。

## 9. 六个月一次的体检

1. 我能不看材料讲清**三个**问题吗？
2. 我最近三个月**算过**什么？（不是读过什么）
3. 我的 `log/` 里，"卡住"的原因是技术还是动机？
4. 有没有一个我**自己提出**的问题？

第 4 条是唯一重要的指标。
